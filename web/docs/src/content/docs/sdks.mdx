<Aside type="note">
  ZeroCode does **not** ship pre-built SDK packages on any registry today.
  The API surface is stable JSON over HTTP, the OpenAPI 3.1 spec is served
  live, and a generator script ships with the repo. Pick the integration
  style that fits your project.

## Option 1 — call the REST API directly

The fastest path for one-off scripts, CLIs, and integration tests. Every
endpoint is documented in the [REST API reference](/docs/api).

<Tabs>
  <TabItem label="curl">
    ```bash
    curl -X POST "$ZC_BASE/v1/submissions?wait=true" \
      -H "authorization: Bearer $ZC_KEY" \
      -H 'content-type: application/json' \
      -d '{"language_id":71,"source_code":"print(\"hi\")"}' \
      | jq -r '.stdout'
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    import os, requests

    r = requests.post(
        f"{os.environ['ZC_BASE']}/v1/submissions?wait=true",
        headers={"authorization": f"Bearer {os.environ['ZC_KEY']}"},
        json={"language_id": 71, "source_code": "print('hi')"},
        timeout=35,
    )
    r.raise_for_status()
    print(r.json()["stdout"])
    ```
  </TabItem>
  <TabItem label="TypeScript">
    ```ts
    const res = await fetch(`${process.env.ZC_BASE}/v1/submissions?wait=true`, {
    ```

## Option 2 — generate a typed client from the OpenAPI spec

The spec is served live at [`GET /v1/openapi.json`](/v1/openapi.json) (OpenAPI 3.1,
generated by [utoipa](https://docs.rs/utoipa) from the Rust handler annotations).
Any OpenAPI generator can consume it.

### Using the bundled driver

`scripts/generate-sdks.sh` is a thin wrapper around
[openapi-generator-cli](https://openapi-generator.tech/) running in Docker —
no Java install required on the host.

```bash
# Defaults: hits http://localhost:8080 and emits python + typescript clients
./scripts/generate-sdks.sh

# Custom target + languages
./scripts/generate-sdks.sh \
  --api-url=https://zerocode.example.com \
  --out=./generated \
  --generators=python,typescript-fetch,go,java
```

Generated code lands under `<out>/<generator>/`. Treat it like vendored code —
commit it to your repo and re-run when the API contract changes.

### Manual one-liner

If you don't want the shell wrapper:

```bash
docker run --rm \
  -v "$PWD:/local" openapitools/openapi-generator-cli generate \
  -i http://host.docker.internal:8080/v1/openapi.json \
  -g python \
  -o /local/zerocode-python
```

## Option 3 — copy the playground's hand-written TS client

The web playground ships a small typed REST client at
[`web/app/src/shared/api.ts`](https://github.com/bhadri01/ZeroCode/blob/main/web/app/src/shared/api.ts).
It's intentionally NOT auto-generated — it handles SSE streaming, the
idempotency-key header, and the typed `Status` discriminated union, all of
which OpenAPI generators tend to flatten or skip.

```ts
import { submit, stream, get, type SubmissionView } from "./api";

const ack = await submit({
  language_id: 71,
  source_code: "print('hi')",
  limits: { wall_time: 5, memory_mb: 256 },
});

const stop = stream(ack.token, {
  onEvent: ({ event, json }) => {
    if (event === "stdout") console.log("out:", (json as any).data);
    if (event === "finished") console.log("verdict:", (json as any).status.kind);
  },
});
```

It's ~330 lines, MIT-licensed via the repo. Copy it as a starting point if
you want full control over the wire protocol.

## What's *not* shipping today

Honest summary of the gaps:

- **No published SDKs.** Nothing on PyPI, npm, crates.io, Maven Central, or proxy.golang.org.
- **No CLI binary.** No `zerocode submit …` tool — use `curl` or the generated clients.
- **No browser ESM package.** The playground's TS client lives in the repo, not as a separate npm package.
- **No long-term type stability guarantees** below v1. We try not to break the API, but the only contract right now is `/v1/openapi.json` itself.

PRs that publish a generated client to a package registry are welcome.
