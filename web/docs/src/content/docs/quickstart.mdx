## Prerequisites

- Linux host, kernel ≥ 5.14 with cgroup v2 (run `mount | grep cgroup2` to confirm).
- Docker 24+ and Docker Compose.
- A spare port for the API (defaults to `8080`).

<Aside type="caution">
  macOS dev machines work for building and running the API, but the sandbox
  worker needs a real Linux kernel. Use `docker compose` on a Linux host (or
  a Linux VM) for the full stack.
</Aside>

## 1. Clone and configure

```bash
git clone https://github.com/bhadri01/ZeroCode
cd ZeroCode
cp .env.example .env
```

ZeroCode runs as an open, unauthenticated backend — no API key to
configure. Restrict who can reach the API port at the network layer
(private subnet, firewall, reverse proxy with its own auth, VPN).

## 2. Bring up the stack

```bash
docker compose -f deploy/docker-compose.yml up -d
```

This starts:

- `postgres` (the queue lives here — no broker needed)
- `zerocode-migrate` (one-shot; applies all SQL migrations)
- `zerocode-api` (REST + SSE on `:8080`)
- `zerocode-worker` (sandbox executor with 8 isolation layers)
- `runner-rootfs-init` (extracts language toolchains into a volume)

## 3. Verify

```bash
curl http://localhost:8080/v1/health
# → {"status":"ok"}

curl http://localhost:8080/v1/ready
# → {"status":"ok","queue_depth":0}
```

## 4. Submit your first program

<Tabs>
  <TabItem label="curl">
    ```bash
    curl -X POST 'http://localhost:8080/v1/submissions?wait=true' \
      -H 'content-type: application/json' \
      -d '{
        "language_id": 71,
        "source_code": "print(\"hello, zerocode\")"
      }'
    ```
  </TabItem>
  <TabItem label="Python">
    ```python
    import requests

    r = requests.post(
        "http://localhost:8080/v1/submissions?wait=true",
        json={"language_id": 71, "source_code": "print('hello, zerocode')"},
    )
    print(r.json()["stdout"])
    ```
  </TabItem>
  <TabItem label="TypeScript">
    ```ts
    const r = await fetch("http://localhost:8080/v1/submissions?wait=true", {
      method: "POST",
      headers: { "content-type": "application/json" },
      body: JSON.stringify({ language_id: 71, source_code: "print('hello, zerocode')" }),
    });
    console.log((await r.json()).stdout);
    ```
  </TabItem>
</Tabs>

The response contains:

- `token` — short-lived submission identifier (24h retention).
- `status` — `{kind, detail?}` discriminated union (e.g. `accepted`, `time_limit_exceeded`).
- `stdout` / `stderr` / `compile_output` — captured output (base64-encoded if `base64_encoded=true`).
- `wall_time_ms`, `cpu_time_ms`, `memory_kb`, `exit_code`, `signal` — telemetry.

## 5. Try the playground

Open [http://localhost:8080/playground.html](http://localhost:8080/playground.html) — the
same API, fronted by a CodeMirror editor with live SSE output. Each
language starts with a snippet that reads stdin, and `stdin` is pre-filled
so Run works on the first click. Switch to the **Tests** tab to feed one
program many inputs at once with per-case pass/fail verdicts.

## 6. Run a batch of test cases

One program, many inputs, one request — see [Batch submissions](/docs/api#post-v1submissionsbatch):

```bash
curl -X POST 'http://localhost:8080/v1/submissions/batch' \
  -H 'content-type: application/json' \
  -d '{
    "language_id": 71,
    "source_code": "import sys\nn=int(sys.stdin.read());print(n*n)",
    "test_cases": [{"stdin":"3"},{"stdin":"7"},{"stdin":"12"}]
  }'
# → { "batch_id": "...", "count": 3, "tokens": [...] }
# then: curl http://localhost:8080/v1/batches/<batch_id>
```
